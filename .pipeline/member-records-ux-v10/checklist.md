# Manual checklist — member-records ux v10 (look rules)

Spec: `docs/specs/member-records/ux.md` (v12). Visual rules have no source-scan tests (D-038): check them here
(by eye, screenshots, axe). Colour rule is guarded by `bun run check:colors`; `components/ui` is not hand-edited.
Log in as a trainer unless stated. Check light and dark theme where a token is named. Widths: 360, 768, 1024, 1440.

## Tokens, fonts, controls (BR-REC-184, 185, 186, 219, 220, 221)
- [ ] Any screen, light: page background is the pale blue-grey, cards are white with a soft shadow. Dark: cards are lighter than the page, no shadow, stronger border. (BR-REC-219)
- [ ] Primary buttons are orange with navy text and a darker orange edge; never white text on orange, in both themes. (BR-REC-186, 219)
- [ ] Orange text (KPI numbers, links in brand colour) is readable on white (AA). (BR-REC-219)
- [ ] Corners look slightly rounded (about 5 px) on cards, buttons and inputs. (BR-REC-219)
- [ ] A destructive button (Archive) and an "Overdue" badge use the same red in both themes. (BR-REC-219)
- [ ] Sidebar is navy in both themes; active item is an orange-tint pill with orange icon and text; no flat grey active state. (BR-REC-185, 186)
- [ ] Each status badge colour matches its meaning: overdue red, due soon / ends soon amber, active / done green, reminder / estimated blue, ended / archived / never recorded grey. (BR-REC-185)
- [ ] Text is Outfit; page and card titles are Poppins semi-bold; nothing looks monospace. (BR-REC-220)
- [ ] Numbers in the Leaderboard, Active plans and the report card line up in columns (equal-width digits). (BR-REC-220)
- [ ] Table headers are small, bold, uppercase, on a muted band; floating labels are not tiny (about 13 px or more). (BR-REC-220)
- [ ] Add member: Name, Phone, Date of birth, a Select and the time-zone box all look the same (white fill, same border); only a disabled field is grey. Also Search box, Textarea. (BR-REC-221)
- [ ] Tab to any control: a solid 2 px orange-ring outline with a small gap, clearly visible in both themes. (BR-REC-221)
- [ ] Network tab on first load: only Outfit is fetched up front; Poppins loads after. (BR-REC-214, 220)
- [ ] Overlays (sheet, dialog, drawer) open without a blurry backdrop and stay smooth on a phone. (BR-REC-211)

## Shell, sidebar, brand, density, width (BR-REC-122, 177, 178, 180, 181, 182, 186, 227)
- [ ] 1440 px: sidebar is open, fixed to the window; only the content scrolls. Collapse it, reload: it stays collapsed with no flash. (BR-REC-177)
- [ ] 768-1023 px: sidebar is collapsed to icons; below 768 px there is no sidebar or tab bar, the top bar shows the menu button "Open menu"; it opens the drawer, closes on a link, Esc, Back and outside tap. (BR-REC-178, 227)
- [ ] From 768 px the sidebar toggle is in the page header, left of the title, not inside the sidebar. (BR-REC-227)
- [ ] Sidebar header shows the orange "F" square and the text "Fionis CrossFit" when open; only the "F" when collapsed (readable text on orange). (BR-REC-186, 227)
- [ ] Active nav item has a 3 px orange bar at its left edge. (BR-REC-227)
- [ ] Collapsed icon buttons are comfortably large on a touch device (44 px). (BR-REC-122)
- [ ] 1440 x 900 mouse: header 56 px, controls 40 px, table rows 48 px. Touch / phone: controls 48 px, taps at least 44 px, rows at least 56 px. (BR-REC-181, 122)
- [ ] From 768 px every screen uses the whole content area (no centred narrow column) with equal 16 px padding on all four sides, header included. (BR-REC-181, 182)
- [ ] No screen scrolls sideways at 360 px. (BR-REC-182)
- [ ] Page header with the one main action stays visible while the content scrolls (desktop); on phone forms the action bar sits at the bottom above the keyboard. (BR-REC-180)
- [ ] Members at 1440 px is a dense table; at 360 px it is rows. Same for Due list and Memberships ending (switch at 1024 px). (BR-REC-183)
- [ ] The Members search is a Name/Email/Phone picker next to the text box (two separate controls with a gap, not one joined box). (BR-REC-201 amended)
